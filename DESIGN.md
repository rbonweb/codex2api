# DESIGN.md — Frontend UI constraints

This file sets the component and layout constraints for `frontend/`. All frontend changes, including code generated by AI agents, must follow it. `frontend/src/lib/uiConventions.test.mjs` enforces the machine-checkable parts in CI.

## 1. Form controls: use the shared components only, do not hand-write them

| Need | Must use | Do not use |
|---|---|---|
| Dropdown | `Select` from `components/ui/select.tsx` (`options` array, `value` / `onValueChange`) | Native `<select>` / custom className strings (such as `selectCls`) |
| Switch | `Switch` from `components/ui/switch` | `<input type="checkbox">` |
| Number input | `DraftNumberInput` from `components/ui/draft-number-input` (with `min` / `max`) | `<Input type="number">` (legacy use only) |
| Text input | `Input` from `components/ui/input` | Native `<input>` |
| A few mutually exclusive options | `SegmentedPillGroup` from `Settings.tsx` | Hand-written button groups |
| Button | `Button` from `components/ui/button`; icons from lucide; loading state uses `RefreshCw` + `animate-spin` | Native `<button>` |

When a new form control is needed, first add a shared component under `components/ui/`, then use it on the page. Do not implement it inline inside a page.

## 2. Settings page layout

- The system settings page is split into tabs: `codex` / `claude` / `antigravity` / `grok` / `appearance` / `general`. The `?tab=` query parameter drives them (`SettingsTabKey`), and only the current tab's content renders at a time. Old `#settings-xxx` anchors map to tabs through `LEGACY_SECTION_TABS`. When adding a configuration block, first decide where it belongs: a block specific to one upstream channel goes in that channel's tab, a block that spans channels goes in `general`, and site branding and background go in `appearance`.
- Inside a tab, group content with `SettingsSection` (`id` / `title` / `description` / `icon`), and wrap each configuration module in `SettingsCard` (`title` / `description` / `icon` / `footer`). When you add or remove a `SettingsSection`, keep `SETTINGS_TAB_SECTION_INDEX` (tab → section directory) in sync. A tab with more than one section renders a centered frosted-glass section pill bar below the tab bar (in the same sticky container as the tab bar) and highlights the current section on scroll. `settingsTabs.test.mjs` checks that every id in the directory matches a section that is actually rendered.
- The tab bar is a `sticky` element in the page flow, not a floating `fixed` one. Section titles (`SettingsSection`) are plain text headings with no primary-colour icon chip. The icon chips in `SettingsCard` use a neutral colour. The primary colour is kept for `tone="danger"` and interactive highlights, so the whole page does not turn into accent colour.
- Save model: switch and dropdown fields take effect immediately through `autoSaveSettingsPatch`. Text and number fields go into `settingsForm`, and the dirty check compares them against the `persistedSettings` snapshot. The `SaveStatusPill` in the page header shows the status, and the bottom action bar appears only when `dirtyCount > 0`. Any new path that writes a server-confirmed value back into the form must also call `setPersistedSettings` / `markPersisted`, or a false "unsaved" count appears.
- Use `SettingField` (`label` / `description` / optional `layout="switch"`) for a single configuration item, and `SettingHelp` for explanatory hints.
- Cross-channel cards placed in the `general` tab must declare the channels they apply to with the `channels` prop (`SettingsCard` and `SettingField` both support it and render `components/ChannelScopeBadges.tsx`). Use `ALL_UPSTREAM_CHANNELS` for all channels, or a narrower `CHANNELS_*` constant defined at the top of Settings.tsx. Check the scope against the backend consumption point, and do not guess from the copy. Cards inside a channel tab count as specific to that channel by default. Add a badge only when the card also applies to other channels (for example, Codex's global auto-pause also applies to Claude's 5h/7d windows).
- Use only the `SETTINGS_FIELD_GRID` / `SETTINGS_FIELD_GRID_3` / `SETTINGS_SWITCH_GRID` constants for grids. Do not hand-write `grid-cols-*`. For a two-column card layout, use `SETTINGS_CARD_GRID_2` (it includes `lg:items-start`, so cards of different heights do not stretch).
- When a card contains only one switch, use `SETTINGS_SWITCH_ROW` (a full row). Do not put it in `SETTINGS_SWITCH_GRID`, which squeezes it to half width and wraps the label. A group of related switch-only settings should not be split into several narrow cards. Merge them into one card with `SETTINGS_ROW_LIST` + `SettingField layout="row"` (`description` shown inline, `help` in a tooltip), one row per setting, following the Codex tab's "Compression and compatibility switches" card.
- Rows that pair a "switch + value" (for example auto-sync + interval) follow the two-column bordered layout of the Codex "Client and fingerprint" section. Copy that structure for new sections of the same kind.
- Monospace content such as version numbers and IDs uses `font-mono text-xs text-muted-foreground`.
- Provider visibility: anywhere the dashboard, account management, or usage channel filters list upstream channels must filter them through `useVisibleChannels()` (`src/visibleChannels.tsx`, driven by `/settings/visible-channels`; the Codex fallback is always visible). Do not hard-code the four-channel list. Add an assertion for a new consumer in `lib/visibleChannels.test.mjs`.

## 3. Copy

- All visible text goes through `t('namespace.key')`. A new key must be written to the same position in all three files: `locales/zh.json`, `en.json` and `zh-TW.json`.
- Use `{{name}}` for placeholders, not string concatenation.

## 4. Guard tests

- When you add or change a settings section, add assertions to the matching source guard test (for example `frontend/src/lib/uiConventions.test.mjs`). They should cover which shared component is used, which API method is called, and that the i18n key exists.
- `uiConventions.test.mjs` scans `pages/` and `components/` (excluding `components/ui/select.tsx`) and rejects any native `<select>`.

## 5. Reference implementations

- Shared dropdown: the timezone / fingerprint mode / platform / version policy fields of the ClaudeCode card in `frontend/src/pages/Settings.tsx`.
- Sync button + auto-sync switch + interval: the Codex "Client and fingerprint" section and the ClaudeCode "CLI version sync" section in Settings.tsx.
